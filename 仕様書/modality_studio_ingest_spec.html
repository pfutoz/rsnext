🎛️ ③ Modality Studio ＆ モダリティ自動取込エンジン仕様書

将来のモダリティ増設・機器更新をブラウザ上から直感的かつおしゃれに完結させる「Modality Studio」の4大機能と、当院5種7台の医療機器＋MALL3患者マスタをリアルタイム処理する Python Ingest Service 群のアルゴリズムを定義します。

🎛️1. Modality Studio（モダリティ設定スタジオ）UI・機能仕様
ノーコード・再起動不要

従来のように新しい医療機器を入れるたびスクリプトの正規表現や設定ファイルを書き換える運用を廃止し、modality_studio.php 上の洗練されたカードUIから誰でも安全に装置追加・ルール調整を行える設計とします。DB（modality_profiles）を毎着信時に高速参照するため、設定変更は保存した瞬間（0秒）から常駐サービスの再起動なしで即時反映されます。

📡 ① 新規装置の自動検出レーダー（Plug & Play）

未登録の新しい装置からテスト画像が1枚でも送信されると、common.py の match_modality_profile() が送信元IP・Calling AE Title・StationName・メーカー・型番・解像度を discovered_devices に自動記録。画面上部に「✨ 新しい装置からの着信を検知しました」カードが出現し、［1クリックで装置登録］を押すだけでマッチ条件が自動入力されたプロファイルが完成します。

📄 ② 業者向け「接続設定案内シート」ワンクリック印刷

医療機器メーカーの設置エンジニアに渡すだけで接続作業が完了するA4案内シートを自動生成・印刷します。
・DICOM送信設定: IP 192.168.1.164 / Port 104 / AE Title: 任意（自動受理）
・FTP送信設定: IP・Port 21・アカウント情報
・フォルダ出力・HTTP API仕様 も1枚に美しく整形出力。

🧪 ③ ドラッグ＆ドロップ振分シミュレータ

手元のサンプルファイル（.dcm, .ECG, .jpg, .pdf）をModality Studio画面へドロップすると、本番DBを汚さずにドライラン解析を実行。「優先度 #20 OLYMPUS_ENDO_FHD にマッチ ➔ 検査名 内視鏡(D) / バッジ色 #0d9488 / O社サークルフィット ON で登録されます」と視覚的にプレビュー表示します。

🌐 ④ 将来フォーマットの間口拡大（DICOM以外も標準対応）

DICOM・フクダ心電図だけでなく、今後クリニックで増えやすい以下のデータ形式を標準サポートします：
・PDF検査レポート（骨密度測定・ABI脈波・ホルタ心電図解析書・睡眠時無呼吸レポート等）
・汎用画像（JPEG / PNG / WebP）（iPad・デジカメによる肛門科・皮膚創部撮影や紹介状スキャン）
・HTTP REST マルチパートAPI（タブレットや院内他システムからの直接POST登録）

検査名自動決定ストラテジー（kensamei_from_tag）仕様
ストラテジー値変換ロジック（ingest_service/common.py 実装準拠）
FIXED 常にプロファイルの default_kensamei を採用（例: フジ内視鏡 ➔ ES_General、オリンパス ➔ 内視鏡(D)、心電計 ➔ 心電図(D)）。

🔢3. 患者ID正規化・旧互換・バーコード誤読検知ルール（normalize_patient_id）
common.py 実装済
  1. Unicode NFKC正規化・前後空白除去: 全角数字で手入力されたID（例: ７０７５５）も自動で半角 70755 に正規化します。
  2. 旧RS-Base 12桁 999999 プレフィックス互換: 999999070755 のような12桁以上の 999999 始まり数字列は下位桁を整数化して 70755 として抽出します。
  3. フクダ心電計 (D) サフィックス抽出: 00083003(D) や 83003(D) 形式から数値部 83003 を自動抽出し先頭ゼロを除去します。
  4. MALL3 DRS2 9番台付与: DRS2\kanja.txt 由来の場合は f"9{val:05d}"（例: 123 ➔ 900123）へ変換し現行RS-Base採番と100%一致させます。
  5. 不正ID・バーコード誤読の確実な Quarantine 隔離: 空欄、NoNumber / Unknown / test / $ / ~ を含む文字列、数値以外、0 以下、または 10桁超過（バーコードリーダーが検体番号等を誤読したケース） はすべて None と判定し、誤った患者やゴミデータとして混ぜず確実に quarantine_queue へ保護します。

① 内蔵FTPレシーバ
ftp_receiver.py		 pyftpdlib ベースの非同期FTPサーバ。FTPHandler.on_file_received(file) コールバックにより、内視鏡からのTCPストリームが完全にクローズされた瞬間にのみファイラーキューへ投入（従来のポーリング方式で起きる「転送途中の半端なDICOMを読んで壊す事故」が原理的にゼロ）。

③ フクダ心電図ウォッチャ
fukuda_ecg_watcher.py		 watchdog で着信フォルダを監視し、ファイルサイズ安定（書込完了）確認後にファイル名および内部バイナリヘッダから患者ID・検査日時（Block 1 タイムスタンプ）を抽出。原本 0001.ECG を格納すると同時に ecg_render.py で波形JSONを cache/ecg_json/ へ先行出力します。

🖼️5. 画像・心電図レンダリングエンジン仕様（dcm_render.py / ecg_render.py）
実装・検証済

🩻 DICOM 適正階調レンダラ (dcm_render.py)

  • カラー画像（内視鏡・エコー RGB / YBR）: 3ch RGB uint8配列として忠実出力。
  • 10/12/16bit グレースケール（島津X線 DX/RF・CT/MRI）: pydicom.apply_voi_lut() で装置推奨の Window Center / Width を適用し、未定義時は RescaleSlope / RescaleIntercept 補正後に最小〜最大ダイナミックレンジ正規化を実施。
  • MONOCHROME1 自動反転: PhotometricInterpretation == 'MONOCHROME1' を自動検知して白黒階調を標準 MONOCHROME2 へ揃えます。

📈 フクダ電子 12誘導心電図デコーダ (ecg_render.py)

  • バイナリ構造解析: オフセット 0x1E のブロックディレクトリを走査し、Block 1 から機種名（FCP-*）・検査日時、Block 3（Tag 0x04）から計測値（HR, RR, PR, QRS, QT, QTcB, QTcF, Axis電気軸）を抽出。
  • 固定ハフマン＋2階差分復号: Block 5（マーカー 00 09 02）の圧縮ビットストリームを専用 HUFF_TREE で復号し、x = 2*prev1 - prev2 + delta で8基本誘導（I, II, V1〜V6）を完全復元。
  • 標準12誘導導出: アイントーベン・ゴールドバーガー則により III, aVR, aVL, aVF をmV単位で算出して高精細JSON出力します。
