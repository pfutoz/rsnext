🏗️ ① インフラ・非RAIDマルチSSD・ディレクトリ構造仕様書

🌐1. ネットワーク・待ち受けポート構成（開発環境 vs 本番環境）

開発・リハーサル環境（現行PC 192.168.1.111）では既存サービスと競合しない高番ポートで検証し、Windows Server 2025 本番切替時には旧サーバと完全同一のIP（192.168.1.164）および標準ポートで待ち受けることで、院内全7台のモダリティおよびMALL3側の設定変更を完全にゼロにします。

💾2. 非RAID 単体NTFS「4TB SSD × 4本 ＋ 8TB HDD」最適配置設計
1分フェイルオーバー対応
💡 なぜハードウェアRAID / 記憶域スペースを組まないのか？
クリニック内運用においてRAIDカード故障やストライプ破損が発生すると、単体ディスクを別PCに繋いでも中身を読めず専門業者待ちで診療停止に陥ります。RS-Nextではすべてのドライブを「どのWindows PCにUSB接続してもそのままエクスプローラで読める標準単体NTFS」とし、アプリケーション層の volume_id 管理と robocopy /MIR ミラーリングを組み合わせることで、安全性と素人保守性を両立します。
ドライブ 物理デバイス RS-Next ボリュームID 格納対象・容量見込み・障害時役割
C: OS用 NVMe SSD システム・キャッシュ Windows Server 2025、PostgreSQL 18 (rsnext_db)、Apache + PHP 8、Python Ingest常駐サービス、高速サムネイル/波形キャッシュ (cache/)、着信ステージング (inbox/)、隔離領域 (quarantine/)。
D: 4TB SSD #1 VOL_ARCHIVE 過去アーカイブ領域（2000年〜2021年）: 旧サーバ移行データのうち2021年以前（約2.2TB）を収容。新規書込は発生せず事実上イミュータブル（読み取り中心）となるためSSD寿命も半永久的。
E: 4TB SSD #2 VOL_ACTIVE 現役データ領域（2022年〜現在＋今後の新規着信）: 移行直後は約1.0TBのみ使用し、残り約3.0TBの余裕（今後約8〜10年分）を確保。将来満杯になっても VOL_ACTIVE_2 を設定1行で追加可能。
F: 4TB SSD #3 mirror_archive_f D: (VOL_ARCHIVE) の完全同期ホットスタンバイミラー: タスクスケジューラの robocopy D:\ E_MIR... /MIR により同一ディレクトリ構造を保持。D: 故障時はドライブ文字を F:➔D: に変えるだけで1分復旧。
G: 4TB SSD #4 mirror_active_g E: (VOL_ACTIVE) の日次/準リアルタイム同期ミラー: robocopy E:\ G:\ /MIR で常時待機。診療中に E: が突然死しても、ディスク管理で G: を E: に変更するだけで即座に診療再開可能。
H: 8TB 大容量 HDD backup_hdd_8tb 3重防御・世代バックアップ保管庫: 毎晩深夜に D:＋E: 差分バックアップおよび PostgreSQL pg_dump 圧縮ダンプ（30世代ローテーション）を保存し、誤消去やランサムウェアにも備えます。
📂3. ディレクトリ階層ルールと自己記述 study_meta.json 仕様

各ボリューム直下の studies/ 配下は、検査日に基づく YYYY/MM/DD の3階層パーティションで整理します。1フォルダ内に1万件以上が並んでいた旧 ImfidxYYYY のボトルネックを解消し、1日あたり数十フォルダの極小リストに保つことでNTFSインデックス性能を最大化します。 

<VOLUME_ROOT>/                                    # 例: E:\rsnext_active (VOL_ACTIVE)
└── studies/
    └── 2026/
        └── 11/
            └── 17/
                ├── P00070755_ES_091522_01/       # 命名規則: P{8桁0埋め患者ID}_{Modality}_{HHMMSS}_{2桁連番}
                │   ├── 0001.dcm                  # 4桁連番 (rsview.exe 等からも順序通り直接開けるクリーン命名)
                │   ├── 0002.dcm
                │   ├── ...
                │   └── study_meta.json           # UTF-8 自己記述メタデータ (アトミック書込)
                ├── P00082751_DX_100418_01/
                │   ├── 0001.dcm
                │   └── study_meta.json
                └── P00083003_ECG_112312_01/
                    ├── 0001.ECG                  # フクダ電子原本バイナリ (FEV-05.exe 完全互換)
                    └── study_meta.json

<CACHE_ROOT>/                                     # 例: C:\rsnext\storage_data\cache (いつでも破棄・再生成可能)
├── thumbs/
│   └── {study_id}/
│       ├── 0001_thumb.jpg                        # 一覧・フィルムストリップ用 (長辺 200px, Lanczos)
│       └── 0001_view.jpg                         # Webビューワ即時表示用フルサイズJPEG (Quality 88)
└── ecg_json/
    └── {study_id}/
        └── 0001.json                             # ecg_render.py 解析済 12誘導波形配列＋計測値JSON
自己修復用メタデータ study_meta.json フォーマット仕様

検査取り込み時、およびWeb管理画面での「所見編集」「患者ID付け替え」実行時には、ingest_service/common.py の atomic_write_json()（一時ファイル書込➔os.replace）を用いて study_meta.json を同時更新します。これにより、万一DBサーバが初期化されてもストレージ走査のみでDBを100%再構築できます。

⚙️4. 設定ファイル config/server_config.json 全キー仕様
構築済
JSON キーパス 型 / 既定値 設定内容・本番切替時の変更指針
karte_url_template String 一覧の患者IDクリック時に開く電子カルテURL。{patient_id} が正規化患者番号に置換されます。
enable_legacy_local_viewer Boolean (false) false（標準）では全端末Webビューワ完結。true にすると watcher.vbs 連携（rsview.exe / FEV-05.exe 直起動モード）も選択可能になります。
jpeg_direct_export_default_dir String 胃がん検診モード（?mode=jpeg）での一発JPEGフォルダ保存の初期出力先親フォルダ。
db.host / port / dbname / user / password Object PostgreSQL 18 接続情報（127.0.0.1:5432, rsnext_db）。Python（psycopg）とPHP（PDO pgsql）双方が共通参照します。
storage.active_volume_id String ("VOL_ACTIVE") 新規着信・Web取込データを書き込む現行アクティブボリュームのキー名。
storage.archive_cutoff_year Integer (2021) 旧RS-Baseデータ移行時の自動振分境界年。2021 年以前は VOL_ARCHIVE、2022 年以降は VOL_ACTIVE へ格納。
storage.volumes.<VOL_ID> Object 各ボリュームのローカル実体パス path、ミラー先 mirror_path、およびレガシービューワ併用時の smb_share UNCパスを定義。
ingest.ftp.port Integer 開発環境 2121 ／ Windows Server 2025 本番では 21 に設定。
ingest.dicom_scp.port / promiscuous_ae_title Integer / Boolean 開発環境 11104 ／ 本番 104。promiscuous_ae_title: true によりAEタイトル不一致エラーを100%防止。
ingest.mall3_csv.drs2_prefix_nine Boolean (true) DRS2\kanja.txt 着信時、RS-Base互換の 9{5桁ゼロ埋めID}（例: 123 ➔ 900123）変換を自動適用。
legacy_rsbase_source Object マイグレーションツールが Read-Only 参照する旧サーバ 192.168.1.164（gazouDB および public_html 共有）の接続定義。
