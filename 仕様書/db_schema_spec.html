🗄️ ② 完全UTF-8 データベース設計書（rsnext_db 全7テーブル定義）

旧 gazouDB（PostgreSQL 9.3 / SHIFT_JIS）における文字コード変換負荷、数値/文字列型不一致による結合インデックス無効化、重複送信登録、無言エラー放置をすべて解決する sql/001_schema.sql の詳細テーブル定義書です。

📐データベース全体構成・リレーション概要
sql/001_schema.sql 実装済 
[patients] (1) ──────────< (N) [studies] (1) ──────────< (N) [study_files]
  patient_id (PK)                study_id (PK)                 file_id (PK)
  patient_no_int (GENERATED)     legacy_renban (UNIQUE)        sop_instance_uid (UNIQUE部分索引)
  kanja_kanji (GIN trgm)         patient_id (FK, CASCADE)      sha256_hash (INDEX)
  kanja_yomi_norm (GIN trgm)     profile_id (FK)
                                 volume_id + rel_path (UNIQUE)
                                       ▲
                                       │
[modality_profiles] (1) ───────────────┴────── (0..N) [discovered_devices]
  profile_id (PK)                                       discovery_id (PK)
  match_rules (JSONB)                                   fingerprint_key (UNIQUE)
  viewer_options (JSONB)                                linked_profile_id (FK)

[quarantine_queue] (隔離救済時に studies.study_id へリンク)     [ingest_logs] (全着信・編集・救済の監査証跡)
🔑 設計上の3大重要ポイント
  • 患者ID付け替えの一括連鎖整合（ON UPDATE CASCADE）: studies.patient_id は patients(patient_id) を外部キー参照しており、新患仮ID統合等にも安全に追随します。
  • 二重取込の物理的ブロック: study_files に sop_instance_uid の部分ユニークインデックスと sha256_hash インデックスを備え、モダリティからの再送操作でもファイルが重複増殖しません。
  • 誤削除からの100%復元（Soft Delete）: 検査削除は物理消去ではなく studies.is_deleted = TRUE とし、通常検索の部分インデックス（WHERE NOT is_deleted）から即座に除外しつつゴミ箱から1クリック復元可能です。
👤1. patients — 患者マスタテーブル
旧 name_tbl 継承・強化

MALL3 の DRS\kanja.txt および DRS2\kanja.txt（21列CSV）からリアルタイム UPSERT される患者基本テーブルです。画像がCSVより先に着信した緊急新患時も仮レコードを自動生成し、後続CSV到着時に正式氏名へ上書き補完します。

🎛️2. modality_profiles — Modality Studio 装置プロファイル管理
Modality Studio コア

院内各モダリティの識別条件（match_rules）、検査名決定ロジック、UIバッジデザイン、ビューワ個別挙動をノーコード管理するマスタテーブルです。現行5種7台＋汎用外部メディアの計7プロファイルが初期プリセットされます。

カラム名データ型制約・既定値説明
profile_idSERIALPKプロファイル内部ID。

device_nameVARCHAR(128)NOT NULL管理画面表示用の装置名称（例: フジフイルム内視鏡 ELUXEO 8000）。
room_or_locationVARCHAR(64)DEFAULT ''設置検査室（例: 内視鏡室 (2台共通FTP), レントゲン室）。
protocolVARCHAR(32)DEFAULT 'DICOM_SCP'受信プロトコル（FTP / DICOM_SCP / FOLDER_WATCH / HTTP_API）。
modality_codeVARCHAR(16)DEFAULT 'OT'標準モダリティコード（ES, DX, RF, US, ECG, DOC, OT）。
display_categoryVARCHAR(32)DEFAULT 'other'UIフィルタ分類（endoscopy, xray, us, ecg, report, other）。
default_kensameiVARCHAR(100)NOT NULL既定の検査名（例: ES_General, 内視鏡(D), 胸部(D), 心電図(D)）。

📡3. discovered_devices — 自動検出レーダー（未登録装置指紋記録）
Plug & Play 登録用

通信が着信するたびに「プロトコル・送信元IP・AEタイトル・StationName・メーカー・機種名・Modality・拡張子」から一意な fingerprint_key を生成して自動記録します。まだ専用プロファイル（linked_profile_id）に紐付いていない新装置は Modality Studio 画面上部に「✨ 新しい装置を検知しました」としてポップアップ表示され、1クリックでプロファイル登録できます。

カラム名データ型説明
discovery_idSERIAL PK検出レコードID。
fingerprint_keyVARCHAR(255) UNIQUE装置指紋複合キー（同一装置からの2回目以降は seen_count 加算・last_seen_at 更新）。
source_protocol / source_ipVARCHAR(32) / (64)着信プロトコル（FTP, DICOM_SCP 等）および送信元IPv4アドレス。
calling_ae_title / station_nameVARCHAR(64) / (128)DICOM Calling AE Title および (0008,1010) StationName。
manufacturer / model_nameVARCHAR(128)(0008,0070) Manufacturer および (0008,1090) ManufacturerModelName。
dicom_modality / sample_resolution / sample_file_extVARCHARDICOM Modality、検出された画像解像度（例: 1920x1080）、ファイル拡張子。
linked_profile_id / is_dismissedINTEGER FK / BOOLEAN紐付け済プロファイルID（未登録時は NULL）および通知非表示フラグ。
